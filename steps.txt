Create docker network:

Step 2.2 — Choose how Jenkins creates temporary containers
To implement your agentless design, Jenkins needs a way to ask Docker to create and remove containers.
We have two main options:
Option A — Separate Docker daemon
[Recommended for our lab]
Run a dedicated Docker daemon in another container. Jenkins uses a Docker client to communicate with it over the private Docker network.
Advantages: avoids giving Jenkins direct access to the host Docker socket. Trade-off: Docker-in-Docker typically needs privileged mode, so it is not a production security boundary.

Option B — Host Docker daemon
Give Jenkins access to the host's Docker socket and install the Docker CLI inside Jenkins.
Simpler, but Jenkins effectively gains powerful control over the host. I don't recommend this for the security-conscious project we're building.

Let's use Option A
Step 2.3 — Download the Docker-in-Docker image
Run this in your WSL Ubuntu terminal:
docker pull docker:dind

Step 2.4 — Start the dedicated Docker daemon
We'll start a separate Docker daemon container on devsecops-net. It will create temporary containers for our pipeline, while Jenkins remains our controller.
Run:
docker run -d \
  --name devsecops-docker \
  --privileged \
  --network devsecops-net \
  --network-alias docker \
  -e DOCKER_TLS_CERTDIR="" \
  docker:dind \
  --host=tcp://0.0.0.0:2375 \
  --host=unix:///var/run/docker.sock


Important security note: Docker-in-Docker typically requires --privileged. Port 2375 is unencrypted and unauthenticated, so we're deliberately not publishing it to the host. Only containers with network access to this daemon should be trusted. This is a practical local-lab setup, not production-grade isolation.

Step 2.5 — Test communication with the Docker daemon
Before modifying Jenkins, let's verify that another container can communicate with the daemon over our private network.
Run:
docker run --rm \
  --network devsecops-net \
  -e DOCKER_HOST=tcp://docker:2375 \
  docker:cli version
Step 2.6 — Build a custom Jenkins image
Instead of installing a full Docker Engine inside Jenkins, we'll copy just the Docker CLI from the official Docker CLI image. This keeps our controller image simpler.

1. Create the Dockerfile
Run these commands in WSL Ubuntu:
cd ~/devsecops-project

mkdir -p jenkins-controller

cd jenkins-controller

cat > Dockerfile <<'EOF'
FROM docker:cli AS docker-cli

FROM jenkins/jenkins:lts-jdk21

USER root

COPY --from=docker-cli /usr/local/bin/docker /usr/local/bin/docker

USER jenkins
EOF

2. Build the image
docker build -t local/jenkins-docker-cli:1.0 .

3. Verify the image
docker run --rm \
  --entrypoint docker \
  local/jenkins-docker-cli:1.0 \
  --version
